# hw4. Сшивка кадров в панораму

## Задача

Для каждой группы изображений из каталогов `building1`, `building2` и
`building3` выполнить сшивку кадров в единую панораму.

В работе два решения. Первое (`lab04`) повторяет метод с практического занятия,
второе (`sift`) — альтернативный вариант на SIFT. Оба лежат в
`hw4/panorama.py` и переключаются флагом `--method`.

## Данные

| Группа | Кадров | Размер кадра |
|--------|-------:|--------------|
| `building1` | 5 | 640×480 |
| `building2` | 4 | 1008×567 |
| `building3` | 5 | 567×1008 (портрет) |

Кадры в каждой группе сняты последовательно с большим перекрытием, поэтому
сшиваются по цепочке: каждый следующий кадр сопоставляется с предыдущим.

## Метод 1 — `lab04`

Повторяет алгоритм с практического занятия:

1. **ORB** (`nfeatures=2000`) находит ключевые точки и дескрипторы.
2. **BFMatcher** с `NORM_HAMMING` сопоставляет дескрипторы соседних кадров
   (`knnMatch`, k=2).
3. Пары фильтруются проверкой отношения расстояний (Lowe ratio test, `0.6`).
4. По хорошим соответствиям оценивается гомография
   `cv2.findHomography(..., cv2.RANSAC, 5.0)`.
5. Кадры переносятся на общее полотно через `cv2.warpPerspective`.

Гомографии соседних пар перемножаются в систему координат опорного кадра.
Опорным выбирается **центральный** кадр: преобразования строятся от него влево
и вправо, поэтому ошибка не накапливается к одному краю и панорама меньше
заваливается.

### Про устойчивость

Фасады зданий состоят из повторяющихся окон. На таких соответствиях полная
гомография легко получает лишние перспективные члены: у матрицы появляется
полюс рядом с кадром, углы уезжают на десятки тысяч пикселей, а полотно
раздувается до гигабайтов. На двух кадрах (как в lab04) это незаметно, но при
перемножении нескольких гомографий ошибка накапливается.

Поэтому после оценки всей цепочки выполняется проверка: преобразование каждого
кадра не должно раздувать его больше чем в 5 раз и не должно сжимать сильнее
чем в 4 раза. Если цепочка гомографий не проходит проверку, группа сшивается
преобразованием подобия (поворот, равномерный масштаб, сдвиг) — это частный
случай гомографии, и он оценивается по тем же самым соответствиям:

```python
S, inliers = cv2.estimateAffinePartial2D(src_pts, dst_pts, method=cv2.RANSAC)
```

На текущем наборе цепочка гомографий устойчива только для `building1`; для
`building2` и `building3` группы сшиты подобием. Гомографии для них тоже
вычисляются и видны в статистике.

## Метод 2 — `sift`

Альтернативный вариант, который тоже даёт устойчивый результат:

1. **SIFT** находит ключевые точки и дескрипторы.
2. **BFMatcher** с `NORM_L2` сопоставляет дескрипторы (`knnMatch`, k=2).
3. Lowe ratio test с порогом `0.75`.
4. По соответствиям сразу оценивается преобразование подобия
   `cv2.estimateAffinePartial2D(... cv2.RANSAC ...)`.
5. Перенос через `cv2.warpPerspective`.

SIFT даёт больше ключевых точек и более точные соответствия, поэтому порог
отношения здесь выше. Гомография не используется: для панорамы из нескольких
кадров подобие устойчивее и не даёт ложной перспективы.

## Общее для обоих методов

После оценки преобразований кадры переносятся на общее полотно и смешиваются
с весами по расстоянию до края кадра (`cv2.distanceTransform`). Края получают
очень маленький вес, центры — большой, поэтому переходы плавные.

В обоих методах опорным кадром выбирается **центральный**. Матрицы строятся от
него влево и вправо, поэтому ошибка не накапливается от первого кадра к
последнему и наклон панорамы заметно меньше.

## Параметры

| Метод | Детектор | Матчер | Ratio | Модель преобразования |
|-------|----------|--------|------:|-----------------------|
| `lab04` | ORB, 2000 точек | BFMatcher, `NORM_HAMMING` | 0.6 | гомография RANSAC 5.0, при неустойчивости — подобие |
| `sift` | SIFT | BFMatcher, `NORM_L2` | 0.75 | подобие RANSAC 5.0 |

## Результаты

| Группа | `lab04` | `sift` |
|--------|---------|--------|
| `building1` | 2099×794 (гомография) | 1552×538 (подобие) |
| `building2` | 2174×686 (подобие) | 2551×828 (подобие) |
| `building3` | 1890×1075 (подобие) | 1901×1076 (подобие) |

Оба метода дают похожие панорамы. Разница — в размерах полотна и в том, какие
кадры сильнее «растянуты»: `lab04` использует ORB и гомографию (с переходом на
подобие), `sift` — более плотные SIFT-соответствия и сразу подобие. На
`building1` `lab04` смог удержать гомографию, поэтому полотно шире; на
`building2` и `building3` оба метода сшиты подобием. Благодаря центральному
опорному кадру все панорамы получились ровнее, без заметного наклона.

Готовые панорамы лежат в `hw4/output/`:

```
output/lab04/building1_panorama.jpg
output/lab04/building2_panorama.jpg
output/lab04/building3_panorama.jpg
output/sift/building1_panorama.jpg
output/sift/building2_panorama.jpg
output/sift/building3_panorama.jpg
```

На панорамах видны чёрные уголки — это области, которые не покрыл ни один кадр
(особенно заметно на портретных кадрах `building3`). Содержимое при этом
сшито без разрывов и дублирований.

## Запуск

Оба метода сразу:

```sh
uv run python hw4/panorama.py
```

Только один метод:

```sh
uv run python hw4/panorama.py --method lab04
uv run python hw4/panorama.py --method sift
```

Пути можно задать явно:

```sh
uv run python hw4/panorama.py --data hw4/data --out hw4/output
```

Скрипт печатает размер каждой панорамы, выбранную модель и число
соответствий/инлайеров по парам кадров, а результат сохраняет в
`hw4/output/<метод>/`.
