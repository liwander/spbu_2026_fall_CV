# hw4. Сшивка кадров в панораму

## Задача

Для каждой группы изображений из каталогов `building1`, `building2` и
`building3` выполнить сшивку кадров в единую панораму. Файл с программой —
`hw4/panorama.py`.

## Данные

| Группа | Кадров | Размер кадра |
|--------|-------:|--------------|
| `building1` | 5 | 640×480 |
| `building2` | 4 | 1008×567 |
| `building3` | 5 | 567×1008 (портрет) |

Кадры в каждой группе сняты последовательно с большим перекрытием, поэтому
сшиваются по цепочке: каждый следующий кадр сопоставляется с предыдущим.

## Метод

### 1. Ключевые точки

На каждом кадре детектор SIFT находит ключевые точки и дескрипторы:

```python
sift = cv2.SIFT_create()
kp, desc = sift.detectAndCompute(gray, None)
```

### 2. Сопоставление

Дескрипторы соседних кадров сравниваются `BFMatcher` (норма L2). Пары
фильтруются проверкой отношения расстояний (Lowe ratio test, порог 0.75):
пара принимается, если лучший вариант заметно ближе второго.

### 3. Преобразование

По оставшимся соответствиям оценивается преобразование подобия
`cv2.estimateAffinePartial2D` (поворот, равномерный масштаб, сдвиг) методом
RANSAC с порогом 3 пикселя. Матрица дополняется до `3×3`, чтобы её можно было
применять через `cv2.warpPerspective`.

### 4. Общее полотно

Преобразования соседних кадров перемножаются в систему координат первого кадра.
По углам всех кадров вычисляются границы общего полотна, и кадры переносятся
на него.

### 5. Смешивание

Чтобы швы были незаметны, каждый кадр входит в панораму с весом, равным
расстоянию от пикселя до края кадра (`cv2.distanceTransform`). Края кадров
получают очень маленький вес, центры — большой, поэтому переходы плавные.

### Почему подобие, а не полная гомография

Фасады зданий состоят из повторяющихся окон. На таких соответствиях
`cv2.findHomography` легко «уводит» перспективные члены: углы кадра уезжают на
десятки тысяч пикселей, и полотно разрастается до неприемлемых размеров
(вплоть до десятков гигабайт). Камера при съёмке движется примерно параллельно
фасаду, поэтому поворота, масштаба и сдвига достаточно. Такая модель устойчива
и не даёт ложной перспективы. В коде стоит предохранитель `MAX_PIXELS` на
случай абсурдно большого полотна.

## Результаты

| Группа | Панорама | Соответствия / инлайеры по парам |
|--------|----------|-----------------------------------|
| `building1` | 1555×609 | 473/182, 1009/579, 164/42, 351/184 |
| `building2` | 2332×830 | 539/136, 980/142, 662/135 |
| `building3` | 1915×1121 | 431/160, 491/158, 409/181, 538/214 |

Готовые панорамы лежат в `hw4/output/`:

```
building1_panorama.jpg
building2_panorama.jpg
building3_panorama.jpg
```

На панорамах видны чёрные уголки — это области, которые не покрыл ни один кадр
(особенно заметно на портретных кадрах `building3`). Содержимое при этом
сшито без разрывов и дублирований.

## Запуск

```sh
uv run python hw4/panorama.py
```

Пути можно задать явно:

```sh
uv run python hw4/panorama.py --data hw4/data --out hw4/output
```

Скрипт печатает размер каждой панорамы и число соответствий/инлайеров по
парам кадров, а результат сохраняет в `hw4/output/`.
